# Elite Parallel Orchestrator

A high-stakes multi-agent system that combines adversarial planning, rigorous validation, and QA automation to produce superior competitive intelligence with ≥95% certainty.

## Core Architecture

### Adversarial Multi-Agent Planning
- Self-orchestrates 5 hostile category members (unspecified-low, unspecified-high, deep, ultrabrain, artistry) via team-mode for ruthless cross-critique debate
- Distills only defensible insights that survive intellectual combat
- Mandatory handoff to the `plan` agent for executable plan formalization

### Verification Framework
- Systemic verification doctrine with forced cognitive exertion
- Zero-tolerance for heuristics or sentiment-based reasoning
- Mathematical proof chains with ≥95% derived certainty
- Saturation loops until "Bedrock" (no new info) is reached

### Quality Assurance System
- Nuclear-grade 12-agent pre-publish release gate
- Per-change deep dive with up to 10 ultrabrain agents
- Holistic review with manual QA plus gate reviewer
- Release synthesis with oracle for overall readiness
- Isolated QA environments that never touch user data

## Execution Workflow

### Phase 1: Adversarial Planning
1. Verify team_mode.enabled is true and you're running as a lead-eligible agent
2. Spawn 5 adversarial category members with distinct prompt characteristics
3. Conduct ruthless cross-critique debate between members
4. Synthesize only defensible insights that survive attacks
5. Hand off distilled insights to the plan agent

### Phase 2: Rigorous Validation
1. Apply TnR ABSOLUTE RIGOR methodology
2. Run through mandatory execution checklist:
   - Inversion: Enumerate and neutralize systemic failure modes
   - First Principles: Axiomatic deconstruction with zero assumptions
   - Multi-order effects: Map 3rd order externalities
   - Circle of certainty: Demarcate known vs. speculative
   - Model-reality reconciliation: Direct testing
   - Internal depletion: Consume all local code/git/logs
   - External verification: Force authoritative sources to yield evidence
   - Core domain saturation: 100% coverage of new/changed logic
   - Boundary penetration: Stress edge cases to failure
   - Systemic collateral: Identify upstream/downstream risks
   - Mathematical proof: Link every claim to atomic source
   - Certainty derivation: Calculate via evidence weight
   - ≥95% threshold: Execute or report systemic failure

### Phase 3: Quality Assurance
1. Run get-unpublished-changes to detect all changes since last release
2. Spawn up to 10 ultrabrain agents for deep per-change analysis
3. Invoke review-work for holistic review
4. Execute oracle for overall release synthesis
5. Verify all release surfaces (components, opencode, codex)
6. Confirm Discord announcement completion

## Critical Constraints

- Model truth gate: Only REAL Anthropic models (Opus 4.5 strongest today, 4.x family is premium tier)
- Frontier waves above 4.5 may only be referenced as pending org:anthropics confirmation
- Fictional/unconfirmed model names must never be routed to or recommended
- Zero-action policy for GitHub mutations during triage
- Evidence rule: Every factual claim must include GitHub permalink as proof
- Isolation QA: Never touch user's real ~/.codex or opencode database
